# Cinematic fullscreen regression

The previous itch build was reproduced in a fresh browser session: the opening was visible, clicking itch's fullscreen control made the game view blank, and clicking the game canvas restored the same advancing video. The fullscreen control is outside the game iframe. Losing focus paused Unity's render loop because gameplay sets `Application.runInBackground=false`.

`JourneyVideoScreen` temporarily keeps that loop running while either film is active and restores the prior background setting on disable or destruction. Normal gameplay retains its 60 FPS limit and background pause policy. Both films now display the decoder's texture in a screen overlay, with aspect-preserving letterboxing recalculated for the current viewport. They no longer depend on an opening camera target or an ending RenderTexture allocated at the old window size. The original MP4 files and their authored dialogue/audio content are unchanged. Web outro playback uses Direct output so its volume and mute choice are respected.

`CinematicPresentationChecks.Run` checks the render lifetime handlers, camera/target detachment, embedded/fullscreen/portrait dimensions, decoder texture replacement, and missing frames. `CinematicIsolationChecks.Run` and `BossExitChecks` continue checking that the outro hides game UI and suppresses the game soundtrack. The final native integration and editor/Web conditional compilation passed. Audio isolation is supported by those native assertions and code inspection; the browser runs below did not include an audio recording or listening check. The browser bridge tests also cover hidden-page/control preservation, denied focus and outer-iframe active-element states.

The first local release Web build was tested in Chrome inside an iframe with an outer fullscreen button. The full opening remained visible through fullscreen and reached Spring; the outro played above UI and reached the menu/certificate flow. That test exposed a separate keyboard handoff: without clicking the canvas, Return could not close Spring's welcome screen. Normal film completion now requests focus on the visible canvas before restoring gameplay's background policy. Cancellation, hidden documents and focused browser form controls are excluded; there is no `window.focus()` call.

The fix passed in the second release export, `Submission-20261121-final`: after outer-button fullscreen and the complete opening, Return closed Spring's welcome and S moved Ambros without a canvas click. The ending also continued through outer-button fullscreen; after it returned to the main menu, Return activated Continue and restored Winter without a canvas click. These were native Chrome input checks on the running Web game. The reviewed export, `Submission-20261121-reviewed`, includes the last name-card clearance adjustment and also passed the intro fullscreen/Return/movement check. Its first resize capture was briefly black, then advancing video returned without input; the persistent-black failure did not recur. Outro browser evidence remains scoped to the second build, whose cinematic code is unchanged. See [submission validation](SubmissionValidation.md) for exact-build results and remaining release checks.
